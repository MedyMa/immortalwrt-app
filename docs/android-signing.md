# Android 安装与签名

从 0.4.21+35 起，主分支发布 `immortalwrt-android-release`，其中包含固定签名的 `app-stable-release.apk`。不再将随机调试签名的 APK 作为发布包。

## 为什么旧版提示程序包冲突

此前 CI 使用临时运行环境生成的调试密钥，并未保存密钥。包名相同但证书不同时，Android 拒绝覆盖安装。提高版本号或修改文件名不能解决证书不匹配。

旧 APK 只有公开证书，不能恢复签名私钥。如无法找回对应旧密钥，迁移到固定签名需要卸载旧版后重新安装一次。卸载会删除本机 App 的连接配置，请先记下连接地址和用户名，并确保仍掌握密码；路由器上的流量数据不受影响。不要将包含凭据的截图公开发布。

以后从同一固定签名构建更新，正常情况下可覆盖安装并保留配置。没有在用户手机验证前，构建通过不代表迁移已经完成。

## 固定签名的保存与验证

- 私钥与密码作为一个 `ANDROID_SIGNING_BUNDLE` 仓库机密保存，禁止提交 Git。
- 公共证书 SHA-256 保存在 `android/signing-certificate.sha256`。准备签名时必须核对一致，机密缺失或证书改变直接失败，不生成替代密钥。
- 依赖安装、测试与无签名 release 构建完成后才提供签名机密；使用 Android SDK 的 `apksigner` 签名并验证 APK，最后清理临时密钥和密码文件。
- PR 仅生成 `immortalwrt-android-unsigned-pr`，不读取发布密钥；该产物不能直接作为更新包安装。
- 私钥另有本地备份，位于 Windows 用户目录下 `.codex/private/android-signing/immortalwrt-app/`。这是敏感文件，应另行安全备份；丢失私钥会影响以后更新。
