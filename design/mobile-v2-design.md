# ImmortalWrt Mobile v2 设计说明

效果图：[四屏预览](mobile-v2.png) · [可缩放 HTML](mobile-v2.html)。图中的数值是设计示意，不是路由器实测。

## 目标与界面

保留独立 Flutter App、只读连接、家外通过 DDnsto HTTPS 查看 MT7988 的定位。总览突出连接状态、最后成功更新时间、当前速率和本次采集会话的 WAN 总量。设备页合并 DHCP 租约和流量客户端，但明确区分“有租约”“有流量记录”“当前在线”：只有路由器提供实时关联或邻居证据时才显示在线。Wi‑Fi 页只展示 MT7988 板载 BE14，不混入 MiWiFi；无法取到射频频段、信道、关联数时显示“未提供”。流量页把 WAN 总量、可归属应用流量和最近一小时曲线分开，并显示曲线接口故障。

连接页沿用系统底部弹层：URL、用户名、密码、HTTPS/本地 HTTP 提示、连接测试和断开连接。默认家外地址为 `https://bananapi.x.ddnsto.com`，本地 HTTP 仅允许 `192.168.2.1`。凭据仅保存在系统安全存储中，ubus 会话仅驻内存。

## 数据与状态

状态分为未配置、连接中、正常、部分数据缺失、会话过期重登中、离线但保留上次数据。页面直接呈现指标与必要的状态反馈，不设置独立说明或注释卡片。网络故障保留最后成功快照，但将其标为过期。TLS、DNS、连接超时、HTTP 状态、ubus 权限不足分别报错；不把证书故障描述成 Wi-Fi 故障。

前台只轮询当前需要的数据：总览取实时速率与简要状态，设备页取租约与流量客户端，Wi‑Fi 页取无线状态，流量页取趋势和应用数据。后台暂停轮询；恢复前台立即刷新。ubus 会话失效时单次自动重登并重试只读请求；认证失败时停止自动尝试，提示用户重新输入密码。并发刷新只有最后一次有效，切换连接后丢弃旧请求结果。

业务代码拆成 `screens/`、`widgets/`、`services/` 和 `models/`，保留现有模型与 JSON-RPC 协议边界。无后台常驻采集、路由器写操作、MiWiFi 统计或 VPN。

## SDK 与交付

Android 使用 Android 17 SDK（API 37）编译，测试目标行为后再将 `targetSdk` 升至 37；最低安装版本不因编译 SDK 升级而自动抬高。CI 显式安装 API 37 和匹配的 Android Gradle Plugin。iOS 使用 Xcode 27 / iOS 27 SDK 构建，保留较低部署目标以兼容旧机型，并在 CI 输出构建工具版本。两端都运行格式、静态分析、单元与界面测试、平台构建。Android 提供可安装测试 APK；iOS 真机包需要 Apple 签名身份、证书和 provisioning profile，凭据未提供前只产出模拟器包。

## 验收

1. 前台连接、后台超过 ubus 超时再返回、远程隧道暂断后恢复，均能显示正确的新鲜度并恢复读取。
2. 每个页面仅请求所需只读 RPC；后台无周期请求；缺失单项数据不抹掉其他页面。
3. 流量单位与 LuCI 同口径，WAN 总量和应用归属总量不混淆。
4. Android 17 SDK 与 iOS 27 SDK 版本在 CI 日志中可核实，双平台构建成功；真机兼容性与签名状态单独记录。
